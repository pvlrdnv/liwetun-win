# LiWeTun 0.1.1+2 — исправление импорта и диагностики

[Скачать ZIP, около 18 МБ](https://github.com/pvlrdnv/liwetun-win/actions/runs/44383033456/artifacts/14463584630).

Изменения: имя, записанное в прямой ссылке TrustTunnel, появляется вместо
«Подключение N». В «Серверы → Технические детали» отображаются hostname и адреса.
Сохранённые ссылки повторно проверяются после открытия; повторный импорт не нужен.
Имена из подписок сохраняют приоритет. При отсутствии имени остаётся нумерация.
Имена, адреса и содержимое ключа не включаются в диагностический отчёт.

Предварительный отказ проверки адаптеров теперь имеет отдельный закрытый код
`adapterPreflightRejected` (10) и понятное сообщение. Защитная проверка не ослаблена.
Это позволяет отличить этот путь от ошибки ядра; причина первоначального отказа
на пользовательском ПК пока не установлена. Не требуется присылать ключ.

## Заменить предыдущую тестовую сборку

Только на отдельном тестовом ПК Windows 10 x64. Корпоративный компьютер исключён.

1. Нажать «Отключить», закрыть LiWeTun вместе с треем. Удалить старую версию через
   «Приложения и возможности». Сохранить старое доверие до успешного удаления.
2. Если установлена именно сборка 44364045177, после её успешного удаления убрать
   прежний тестовый сертификат в PowerShell от администратора:

   ```powershell
   certutil -delstore Root 3604B5653AD18DA11E0041431A04DF2E8C773381
   ```

3. Сверить новые хэши. Далее следовать `README_RU.txt`: установить доверие новому
   публичному CER и запустить новый установщик. Установка поверх не поддерживается.
   Защищённое пользовательское хранилище удалением приложения не очищается.
4. Под тем же пользователем открыть приложение; проверить имя сохранённого
   подключения и технические детали. После разрешённой попытки подключения на
   отдельном чистом ПК экспортировать **новый** отчёт из «Поддержки».

После завершения теста сначала удалить приложение, затем только новый сертификат:

```powershell
certutil -delstore Root 01F84C7F96A6F50112BBE43C43CE48153C11F4D0
```
